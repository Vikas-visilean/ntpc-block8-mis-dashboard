# How to implement the new design in the MIS dashboard

This guide moves the design built in `index_v1.html` into the live NTPC Bikaner Block 8 dashboard in the repo
[`Vikas-visilean/ntpc-block8-mis-dashboard`](https://github.com/Vikas-visilean/ntpc-block8-mis-dashboard) (published as `v3/`).
**Only the look and layout change.** Every calculation, filter, drill-through, sync check and data feed stays exactly as it is in the repo today.

Prepared on 07-Oct-2026 against repo commit `87cb4e3`, the latest commit to touch the template at the time.

---

## 1. Where the change goes

| Item | Path in the repo | Touch it? |
|---|---|---|
| Dashboard template (HTML + CSS + JS) | `scripts/ntpc_dash_template_v3.html` | **Yes, the only file that changes** |
| NTPC build script | `scripts/build_ntpc_dash_v3.py` | No |
| Other projects' build script | `scripts/build_dash.py` | No |
| Data pullers (VisiLean → JSON) | `scripts/ntpc_dash_data_v2.py`, `scripts/dash_data.py` | No |
| Portfolio build (replays the template's formulas) | `scripts/build_portfolio.py` | No |
| Built page | `v3/index.html`, `v3/meta.json`, `v3/version.json` | Never by hand; regenerated by the build |

`v3/index.html` is **generated**. `build_ntpc_dash_v3.py` takes the template and swaps in four placeholders:
`__DATA__` (the live VisiLean JSON), `__LOGO__`, `__SYNC__` and `__BUILD__`. Do **not** copy `index_v1.html` over `v3/index.html`.
That file is a snapshot with frozen data, and the next sync would overwrite it anyway.

> **This template is shared by every project.** `scripts/projects/*.json` sets no `template` key, so `build_dash.py` also builds
> **Adani S6a, Adani S7, Floating, SJVN and Talaja** from `ntpc_dash_template_v3.html`. Each of them picks up the new design on its
> next refresh. Their calculations are unaffected for the same reason NTPC's are (see §2). If you want NTPC first, see §6.

## 2. Do-not-touch list (calculation and logic)

The patch was generated so that none of the following changes. This was verified mechanically: the function text is identical before and after.

- **Progress maths:** `wgt`, `wsum`, `planPct`, `actPct`, `actPctAt`, `fcPct`, `pctOf`, `elapsedOf`, `unitVal`.
- **Filters and status rules:** `filtered`, `isDone`, `isDelayed`, `isWip`, `isStopped`, `isLateStart`, `isCrit`, `isPredDelayed`, `statusMix`, `rowStatus`.
- **S-curve data:** `scPeriods`, `scVals`, `scXof`, `scBarMax`, `scPeriodDrill` (the new charts *read* these and never recompute).
- **Cards' data:** `stageKey` (stage buckets), `reasonsFor`, `rsnRecords`, `longLeadItems`, `kpiDrill`, `wdate`, `fmt1`.
- **KPI counting:** `kpiCards` keeps the repo's 07-Oct rules. Delayed and Completed include milestones (`dlAll`, `doneAll`), and the Total wording is unchanged. Only the card *markup* gets an icon and a coloured value.
- **Upstream features added after the design was made** are kept as they are:
  - the nested activity rows in drill tables (`kidrow`, `withKids`);
  - the drawing drill (Task ID column, twin-drawing warning);
  - the milestone-aware `withMs` in `kpiDrill`;
  - the `.wtag` "Weightage based" tag on the old gauge.
- **Placeholders and the data line:** the template must still contain `const DATA = __DATA__;` on its own line.
  `build_portfolio.py` reads every project page with the regex `const DATA = (\{.*?\});\n`, so that line's format must not change.
  `__LOGO__`, `__SYNC__` and `__BUILD__` also stay where they are.
- **Hashes and sync:** `.datahash`, `.tplhash`, `version.json`, `BUILD_ID`, the Refresh button's `meta.json` check, and the 60-second new-build poll are all untouched.

Display wording that changed on purpose (not calculation):
- "pts" is shown as "%" (e.g. Variance `−3.8 %`).
- The "N due to predecessor" chip is no longer shown on the Delayed card; the drill still marks those rows.
- Milestone cards show the VisiLean status instead of "on plan".

## 3. What the new design looks like (final state of `index_v1.html`)

**Every page** follows one flow and one design system:

1. **Banner (hero)**
   - A navy gradient with an eyebrow (Project / Department), the page title, and "project · client · Data as of" with a status badge.
   - Refresh, PDF and a round light/dark theme toggle sit at the top right.
   - Four glass tiles. Actual progress is coloured by status, and Variance is coloured green when ≥ 0 and red when < 0.
   - The filter bar sits inside the banner. The As-of slider is wider and updates when you release it.
2. **KPI row:** Total, Completed, Delayed, In progress, Stopped, Forecast vs Baseline. Each card has an icon tile and a coloured value, and still drills through on click.
3. **The page's own cards**, in the shared card style: 14px radius, 14.5px titles, pill toggles and line legends.

**Banner tiles per page:**
- Project Summary: Actual · Variance · SPI · **Days to COD**.
- Activity pages: Actual · Variance · SPI · **Completed**. Days to COD stays on the summary only (KP 07-Sep).
- Constraints Log: Total · Open · Closed · Linked.

**Project Summary**, top to bottom:
- **Overall progress:** a Chart.js half-gauge (actual ring inside the plan ring) with an "ⓘ weightage-based" note.
- **EPC bifurcation:** three tiles with On plan / Behind / Well behind badges (within 2% · 2–10% · over 10% behind) and actual→plan bars.
- **Reasons for Variance** (span 5) and **Long Lead Item Delivery Status** (span 7), both fixed at 425px:
  - The reasons donut is Chart.js; click a slice to filter.
  - Long Lead shows its 5 stats evenly spaced plus the next 5 deliveries (Wt %, baseline, forecast, delay, status).
- **Key Milestones:** the existing track, with each card showing the VisiLean status plus "+N days", "N days ahead" or "on baseline".
- **S-curve:** same look as `index_portfolio.html`:
  - A statline above the chart (Actual / Plan / Gap at the data date).
  - Straight lines, a dot on each actual month, a shaded actual area, "Data date" marker, and end labels ("6.5%", "Plan 10.3%").
  - A 0/25/50/75/100 y-axis, "Sep 26" month labels and a line legend underneath.
  - The tooltip sits above the plot with a vertical guide line.
  - Monthly: no scrollbar. Weekly: every week labelled, one horizontal scrollbar for both charts, % axis pinned.
- **Stage progress:** Chart.js horizontal bars, actual (coloured by status) against baseline plan.

**Department pages:** banner → KPI row → the summary's Overall progress gauge (span 4) beside Reasons for Variance (span 8) → the department's existing cards.
Stage progress and Sections use the same Chart.js bars.

**Sidebar:** line icons for Project Summary, Plant Layout, Package Pipeline and Constraints Log. The open page shows as a navy pill.

**Behaviour details:**
- Charts animate only when their numbers change.
- Tooltips use the page's shared `#tip`, so they are never clipped.
- Chart hover and clicks are corrected for the page's CSS zoom (`psZoomFix`).
- Charts redraw on theme switch.
- **Fallback:** Chart.js 4.4.1 loads from cdnjs. If it cannot load (offline, blocked CDN), every page falls back to the original SVG cards, which are still in the template.

## 4. Apply it

### Option A (recommended): apply the patch

`new_design.patch` (next to this file) is a standard git diff of `scripts/ntpc_dash_template_v3.html`. It was checked with
`git apply --check` against the repo, and it also reproduces the result of the step-by-step appendix exactly.

```bash
git checkout -b new-design            # work on a branch
git apply --check new_design.patch    # dry run - must print nothing
git apply new_design.patch
git diff --stat                       # expect: 1 file changed, scripts/ntpc_dash_template_v3.html
```

If `git apply --check` fails, the template has changed upstream since commit `87cb4e3`. Use `git apply -3 new_design.patch` to get a
three-way merge, or follow Option B for the hunks that did not apply.

### Option B: apply by hand

Follow the **Appendix** at the end of this file. There are 56 exact Find → Replace steps in file order, each anchored on text that occurs
once in the template. Work top to bottom; after each step the next Find still matches.

### Then preview locally (no VisiLean token needed)

The real build needs `scripts/ntpc_dashboard_data_v2.json`, which only the sync creates. To preview, reuse the data already embedded in
the published `v3/index.html`. Save this as a throw-away script in the repo root (do not commit it) and run `python preview.py`:

```python
import re, json
live = open("v3/index.html", encoding="utf-8").read()
data = re.search(r"const DATA = (\{.*?\});\n", live, re.S).group(1)
tpl  = open("scripts/ntpc_dash_template_v3.html", encoding="utf-8").read()
logo = "data:image/png;base64," + open("scripts/kp_logo.b64", encoding="ascii").read().strip()
sync = json.dumps({"repo": "Vikas-visilean/ntpc-block8-mis-dashboard", "workflow": "refresh-v2.yml"})
html = (tpl.replace("__LOGO__", logo).replace("__SYNC__", sync)
           .replace("__DATA__", data).replace("__BUILD__", "preview"))
open("preview.html", "w", encoding="utf-8").write(html)
print("open preview.html in a browser")
```

## 6. Roll-out notes

- **When NTPC v3 goes live:** `refresh-v2.yml` builds v2 and v3 together but only publishes when **v2's** `.datahash` or `.tplhash` changes. A change to the v3 template therefore goes live with the next refresh that brings new VisiLean data. That usually happens the same day, at the 10:00 or 16:00 IST run. To publish immediately, run `python scripts/build_ntpc_dash_v3.py` locally after a sync has produced the data file, then commit `v3/`. You can also wait for the next data change.
- **Other projects:** Adani S6a, Adani S7, Floating, SJVN and Talaja publish when their own `.tplhash` changes, so they switch to the new design on their **next scheduled refresh** after the template is merged.
  - They rely on optional config (`CFG.plantLayout`, `blockDrill`, `procDatesCard`, and so on). The design keeps every one of those branches, but give each project a quick look after its first new build.
  - If you want **NTPC only** first, save the patched file as `scripts/ntpc_dash_template_v4.html` and point `build_ntpc_dash_v3.py` at it. That is a one-line template-name change in a build script, with no logic involved. Move the others over later by adding `"template": "ntpc_dash_template_v4.html"` to their `scripts/projects/<key>.json`.
- **Rollback:** revert the template commit; the next refresh rebuilds the old look.
- **`index_v1.html` and `index.html`** in the design workspace are references only. The repo's source of truth is the template.
